# 评测集（eval set）使用手册

积累「特定战场场景 → 各动作评分」的标注数据，用于持续验证 **prompt 质量** 和 **模型质量**。

---

## 一、这是什么

对战中，每个决策点有 N 个可选动作（招式 + 换人）。评测集把「某个值得考的场景」固化下来，并给每个动作打分（0~100）。之后每次改 prompt 或换模型，都能跑一遍评测集，看 DS 的决策是否变好/变差。

一句话：**这是给 AI 决策出的「考卷」，评分标准由你（玩家）来定。**

---

## 二、测试使用（怎么跑）

### 前置

1. 已构建知识库：`node po-pokellmon/build-knowledge.js`（首次或数据变更后）
2. 启动决策服务：`node po-pokellmon/server.js`（评测脚本要调它的 `/choice`）

### 跑评测

```sh
node po-pokellmon/eval/evaluate.js
```

输出示例：

```
[001] 100分 无极汰那对苍响：污泥波2x克制最优 => got attack:2 (100分)
[002]  50分 ... => got attack:1 (50分)
[003] 未评分，跳过

==== 统计 ====
已评分: 2 | 待评分: 1
平均分: 75.0
满分(100): 1/2
及格(>=50): 2/2
低分(<50) ids: （无）
```

### 指标含义

| 指标 | 含义 |
|---|---|
| 平均分 | 整体决策质量（越高越好） |
| 满分(100) | 选到最优解的比例 |
| 及格(≥50) | 选到「可接受」以上动作的比例 |
| 低分(<50) | 选错/选无效动作的 case，重点看 |

## 三、数据格式

文件：`cases.jsonl`（每行一个 case，JSON）

```json
{
  "id": "001",
  "desc": "无极汰那对苍响(Fairy)：污泥波2x克制最优",
  "source": "logs/deepseek_20260911_battle8802.log",
  "state": { "...决策时的完整战场状态（复用 log 里的 state 快照）..." },
  "scores": {
    "attack:0": 0,
    "attack:1": 50,
    "attack:2": 100,
    "attack:3": 0,
    "switch:1": 30,
    "switch:2": 30
  },
  "reason": "污泥波(Poison)对苍响(Fairy)2x克制最优=100；喷射火焰1x可接受=50；极巨炮/无极光束龙系对妖精无效=0；换人无明显收益=30"
}
```

### 字段说明

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | 是 | 唯一编号（递增） |
| `desc` | 是 | 场景一句话描述（说清在考什么） |
| `source` | 否 | 来源 log 文件（可追溯） |
| `state` | 是 | 决策时战场状态（直接复制 log 里的 `state`，含 `me.moves[].slot`、`bench[].slot`） |
| `scores` | 否 | 各动作评分。**缺省 = 待评分**，评测时跳过 |
| `reason` | 否 | 标注理由（建议评分后补上） |

### scores 的 key 规则

- `"attack:N"` → 招式槽位 N（0~3），N 对应 `state.me.moves[]` 里的 `slot` 字段
- `"switch:M"` → 换人槽位 M（1~5），M 对应 `state.bench[]` 里的 `slot` 字段

> 用 **slot 而非选项编号**：选项编号（1~9）是动态生成的，同一场景换招式顺序编号就变；slot 是稳定的。

## 四、评分约定

| 分数 | 含义 | 例子 |
|---|---|---|
| 100 | 最优解（你最想用的动作） | 用 2x 克制招式 |
| 50 | 次优但可接受 | 用 1x 本系招式 |
| 0 | 错误/无效 | 对免疫属性用招式、无意义换人 |
| 30 / 70 等 | 中间值自由发挥 | 换人收益不大=30、能逼换=70 |

评分由你（玩家）判断，我按你的标注写入 `scores` + `reason`。

## 五、场景积累（怎么入库）

分两阶段，可异步进行：

### 阶段 1：先囤场景（不评分）

你从 `logs/` 里指出值得入库的场景，我提取 `state` 快照，写成**没有 `scores` 的 case**（评测时标「未评分，跳过」）。

```json
{"id":"002","desc":"...","state":{...}}
```

### 阶段 2：后补评分

你有空时给该场景每个动作打分 + 写理由，我补上 `scores` + `reason`。

### 值得入库的场景类型（供参考）

| 类型 | 例子 |
|---|---|
| 属性克制 | 多招式里选 2x/4x 克制的（别选免疫/抵抗的） |
| 锁招处理 | Choice/Encore 锁招时 DS 是否避开被锁招式 |
| 换人时机 | 是否该换人规避威胁、是否恐慌换人 |
| 异常状态 | 对手已中毒是否还重复下状态、已烧伤是否用物攻 |
| 特性/免疫 | 对储水/漂浮/避雷针等免疫特性的应对 |
| 残血收割 | 是否选能确保击杀的招式 |

> 你只需说「这个场景值得入库 + 为什么」，具体 state 提取和格式我来做。
